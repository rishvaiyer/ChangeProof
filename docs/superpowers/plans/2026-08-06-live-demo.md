# One-Command Live Demo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add `make live-demo` and `make demo-stop` so a presenter can build actual SonicLedger test data, seed DataHub, prove live MCP lineage, and run ChangeProof with live evidence.

**Architecture:** Refactor analysis composition so bundled and live DataHub evidence share the same deterministic impact and remediation engine. Use a FastAPI app factory for evidence-provider injection, then orchestrate dbt, DataHub, MCP verification, and Uvicorn through bounded lifecycle scripts.

**Tech Stack:** Python 3.12, FastAPI, pytest, Bash, dbt, DuckDB, DataHub Quickstart, DataHub MCP, Uvicorn, Make

## Global Constraints

- Hosted Railway behavior remains bundled and credential-free.
- Live mode is enabled only by `CHANGE_PROOF_EVIDENCE_MODE=datahub`.
- Live failures are visible and never silently fall back to bundled evidence.
- The demo uses realistic synthetic SonicLedger data, not production data.
- Dashboard PID handling is repository-local, ignored, and limited to the recorded process.
- Startup and health waits are bounded.
- The feature covers only the prepared `artist_id` type change.
